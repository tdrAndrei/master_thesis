\section{\label{sec:conclusion}Conclusion}

With respect to RQ1, our Statix implementation shows that scope graphs can
provide the binding information required by higher-order pattern unification:
the variables a solution may use are obtained from the scope graph and used to
construct well-scoped higher-order solutions. Metavariables additionally need
state that is visible independently of the lexical scope in which a solution is
found, which led to the separate metavariable scope of \cref{sec:Inference}.
With respect to RQ2, the comparison with Elpi shows that HOAS delegates lexical
binding, capture-avoiding substitution, and higher-order unification to the
meta-language, whereas scope graphs make these operations explicit but directly
support non-lexical name resolution, including modules, qualified references,
and forward references. Overall, higher-order pattern unification is compatible
with scope-graph-based name binding. The main remaining limitations stem from
the solver behaviour that a more complete elaborator requires, not from scope
graphs themselves.

\subsection{Future Work}
\label{sec:future-work}

\paragraph{Constraint postponement and reactivation.}
The most immediate limitation is the absence of constraint postponement. A
constraint outside the pattern fragment may become a pattern problem after later
instantiations, so it should be suspended and reactivated when one of its
metavariables is solved, rather than rejected eagerly.

\paragraph{Pruning.}
A proposed solution may mention a variable outside the metavariable's context
only because that variable is an argument to another metavariable. Pruning that
other metavariable's context removes the offending dependency and would let the
solver handle more higher-order constraints.

\paragraph{Closer integration with the Statix solver.}
Metavariable state is currently passed explicitly through a separate chain of
scopes, because scope-graph bindings are immutable and the state of Statix
unification variables cannot be inspected. Letting Statix unification variables
depend on a local context, or exposing their state, could remove much of this
explicit state management.
